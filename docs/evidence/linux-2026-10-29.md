# Linux Final QA Evidence (2026-10-29)

Sanitized final qualification summary for flyingnobita-agent-profiles v0.1.0,
reviewed at commit `2bd6013`. Only generic paths, versions and results are
published here. Raw QA logs stay private because they can contain account
identifiers, session output and host-specific paths. The earlier offline summary
in [linux-2026-10-28.md](linux-2026-10-28.md) is retained as historical evidence
with its original paths and results.

## Environment

- Linux x86_64 host, disposable profiles with a synthetic home directory.
- Startup, discovery, authentication and sandbox checks run offline
  (`bwrap --unshare-net`); no model call and no credential value was used.
- Docker QA used test-owned `archlinux:latest` and `ubuntu:24.04` containers with
  a temporary home, a temporary mise configuration and the published skill copy.
  Containers, images and networks created for QA were removed, and the pre-QA
  inventory was restored.
- No host `setup --apply`, no login, no credential read-out and no publication
  occurred during QA.

## Claude Code Sandbox Enforcement (final)

An independent final probe at Claude Code 2.1.312, with the pinned native CLI
and a synthetic placeholder API key approval only (no real credential), a
private cache bind, a private temporary directory and offline namespaces:

- a single shell-mode command created a controlled file inside the workspace;
- a controlled write outside the workspace was denied and no such file existed;
- the probe reported `inside_created: true`, `outside_absent: true`,
  `denial_observed: true` and `pass: true`;
- no network or model call occurred, and all owned processes were stopped.

The initially shipped PTY driver runs did not complete this check: they hit
terminal input-timing problems and resolved a non-native launcher. Those
failures are retained privately and are not claimed as green. The final focused
probe changes input timing, pins the native CLI and binds a private cache; it
does not replace the shipped driver's history.

## Docker Prerequisite Installation (final)

Both approved images started without bubblewrap and installed it for real
through `setup --apply`:

| Image | Installed prerequisites |
| --- | --- |
| `archlinux:latest` | bubblewrap 0.13.1-1, git 2.56.0-1, python 3.14.8-1 (pacman) |
| `ubuntu:24.04` | bubblewrap 0.9.0-1ubuntu0.3, git 2.43.0-1ubuntu7.4, python3 3.12.3-0ubuntu2.1 (apt-get) |

- Preview snapshots before and after were byte-identical, and a repeated apply
  produced identical deployed snapshots (idempotent deployment).
- Exactly two versioned task shims were written, carrying the managed-by marker
  and a release path, and the released helper reports version 0.1.0.
- The `agent-profiles-init` task initialized a profile through mise.
- Default Docker seccomp and user-namespace restrictions apply: the namespace
  probe reports the restriction, the profile `run` exits 69 with the cause, and
  no bypass was attempted. **Full profile execution inside default Docker is not
  claimed**; only prerequisite installation, deployment, tasks, `doctor` and the
  truthful refusal are qualified there.

## Public Workflow (final)

Twenty end-to-end commands passed against the reviewed product bytes: two
profiles in one checkout, subdirectory working directory and byte-exact argument
forwarding, host mise directory preservation, selective reset and removal,
sentinel files and unrelated Git excludes preserved, mixed legacy migration with
a private backup content hash, fault interruption at 137, stale-journal refusal
at 77, recovery, and post-recovery run integrity. Clean local installation
passed in both symlink and copy modes with the source copy removed afterwards.
The versioned artifact was verified by checksum, extraction, `--version` and
`doctor --json`.

## Host Configuration Preservation

- The user's current Codex settings are retained: an unattributed setting change
  during a paused QA interval was accepted as-is, with no restore and no
  configuration write. Equality across that original interval is **not**
  claimed.
- A fresh controlled audit then ran Codex 0.165.0 startup, discovery,
  authentication, sandbox and cleanup while comparing 211 selected persistent
  settings, configuration, credential and mise paths by content hash and stat
  metadata: all compared paths were equal, including the Codex configuration.
  Credential values were never read out.
- Regenerated caches, transcripts, conversation databases and update metadata
  are classified as expected volatility rather than configuration equality.
