# Linux Evidence Summary (2026-10-28)

Sanitized summary of the Linux qualification evidence for
flyingnobita-agent-profiles v0.1.0. Only generic paths, versions and results are
published here. Raw QA logs stay in a private evidence directory because they can
contain account identifiers, session output and host-specific paths.

## Environment

- Linux x86_64 (Arch-family distribution) in disposable profiles under a
  temporary synthetic home directory.
- Startup and discovery run offline inside the profile namespace
  (`bwrap --unshare-net`), so no model call or credential use was possible.
- Synthetic host configuration, skill and credential markers live in the
  temporary home; their content hashes were compared before and after each run.
- No real host agent configuration or credential was copied, linked or read.
- Every QA process was started in its own process group, recorded, and stopped by
  that group after confirming the QA profile marker in its environment.

Version probes are informational only. They are not startup, discovery,
authentication or sandbox evidence.

Credential-dependent gap: model responses and model-driven skill invocation were
not run.

## OpenCode 2.2.0

| Class | Result |
| --- | --- |
| Version | 2.2.0 from `opencode --version` and a doctor presence probe (informational) |
| Startup | The normal TUI reached the composer offline and listed the profile skill in `@` completion |
| Discovery | `debug paths` keeps config, data, state and cache inside the profile; `OPENCODE_CONFIG_DIR` replaces the profile XDG configuration root and the synthetic host configuration source is not loaded; profile A and profile B list only their own skill plus repository and bundled sources; profile A's skill activated against a private server with its marker recorded, and profile B refused that skill id; configuration diagnostics reported sources only |
| Auth | `auth list` printed no credential value and no environment source for the synthetic profile file; an inherited environment credential is classified as environment by name only; doctor separates profile files from environment variable names without values. | Sandbox | Not claimed: no enforced denial surface was exercised without a model turn. A harmless shell command ran inside the profile without a model turn, which shows routing, not sandbox enforcement |

Credential-dependent gap: a minimal model response and a model-driven skill
invocation were not run. Shared limits: a host-wide OpenCode background service
listens on the default port `49374` and QA never connected to it (private
`--standalone` servers only); the CLI reports a shared temporary path
(`/tmp/opencode`) that profiles do not redirect; no QA-profile process or
test-owned socket remained after cleanup.

## Cross-Cutting Results

- Profile directory redirection was proven by marker writes landing in the
  profile, not in the synthetic home, for every integration.
- Profile A/B separation was proven for settings, skills and MCP/plugin sources;
  no cross-profile marker leaked.
- Synthetic host markers and their hashes were unchanged after every run.
- Owned-process cleanup left no QA-profile process behind.

## Not Covered by This Summary

- Live model responses and model-driven skill invocation (credential-dependent
  gaps, listed per integration above).
- Model-turn command execution and sandbox denials for Antigravity CLI and
  OpenCode.
- macOS: not qualified and deferred; no macOS result is claimed.
- Final QA items that are still pending and therefore not claimed here: the real
  host's persistent agent configuration audit by `stat` and content hash around
  QA runs, and the Docker container exercise in which `setup --apply` actually
  installs a real missing prerequisite package.
- Repository-source installation, which requires a published repository. Only
  local-source installation is verified for this release.
