# macOS arm64 evidence summary

Sanitized summary of the macOS qualification run. The tested host is a MacBook
Pro with an Apple M4 (arm64) running macOS 27.2, stock `/bin/bash` 3.2.57, and no
Homebrew. Tools came from the repository's own pins through mise, installed into
a disposable prefix; the branch was transferred as a Git bundle and tested from a
disposable clone. Raw logs stay private.

## Skips on this host, and why they are not a green badge

- 13 tests in `tests/02-runtime/mounts-bwrap.bats`: Linux-only bubblewrap
  bind-mount validation. Darwin redirection has no mounts to validate, and its
  behaviour is covered by `tests/02-runtime/darwin-run.bats`.
- `procscan: detects uninspectable orphaned process under AP_PROC_ROOT`: a
  synthetic procfs fixture. Darwin fail-closed behaviour is covered by
  `tests/08-lifecycle/darwin-procscan.bats`.
- `agy is not installed on this host` and `opencode is not installed on this
  host`: no agent CLI was installed on the qualification host.

## Known limits

- Configuration redirection is weaker than the Linux mount layer. A process that
  ignores the redirect variables still sees host paths, and native macOS services
  (the Keychain, caches written by Apple's own `python3`) remain shared. The
  helper suppresses its own bytecode writes so a profile run does not modify the
  host home.
- Network not blocked, shared with the host: the Darwin design has no network
  namespace and the live scripts ran with the host network. No offline
  containment is claimed on macOS arm64, unlike the Linux `bwrap --unshare-net`
  runs.
- `agy` has no configuration-directory variable, so its `.gemini` isolation
  depends entirely on the profile `HOME`.
- Process inspection uses the system `ps`, `sysctl` and `lsof`. Where that
  inspection is unavailable, lifecycle mutations fail closed rather than assume
  the profile is free.
