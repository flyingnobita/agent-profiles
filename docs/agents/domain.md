# Domain docs

This repository uses a single-context layout.

Before exploring, read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.
If a document is absent, proceed silently. Domain documents are created when
terms or decisions are resolved, rather than scaffolded upfront.

Use the vocabulary defined in `GLOSSARY.md`. Note terminology gaps for
`mattpocock-domain-modeling` instead of silently introducing synonyms.
Surface conflicts with existing ADRs before proposing a different decision.
